# SkyForged roadmap

This roadmap prioritizes credibility, reliability and practical usability over expanding the number of pages.

## Foundation

- [x] Browser-based multi-module site with no application backend
- [x] Build planning, RF calculation, reference and educational map modules
- [x] Public quick-start and contribution documentation
- [x] CI for source syntax and local resource checks
- [ ] **Choose and publish a source license** after reviewing third-party asset and dataset rights
- [ ] Confirm a stable public deployment URL and add it to the repository About field and README

## Engineering data quality

- [ ] Add source/revision metadata to catalogue records
- [ ] Label missing, estimated and verified component specifications separately
- [ ] Add numerical test cases for every engineering calculator
- [ ] Document edge cases and assumptions in compatibility checks
- [ ] Review cost entries and avoid implying live retailer prices

## User experience

- [ ] Run keyboard-only and mobile accessibility reviews
- [ ] Add concise examples of complete builds with documented design decisions
- [ ] Provide in-page links from calculations to their engineering assumptions
- [ ] Improve empty states and error messages in the component search/builder

## Governance and safety

- [ ] Keep airspace map clearly labelled as an educational demonstration
- [ ] Consider replacing the simple example buffer map with official, licensed and updateable data **only if a reliable source and maintenance process exist**
- [ ] Add an explicit provenance and update date to platform facts
- [ ] Add maintained automated tests for browser interactions

Success means independent users can run the site, understand every estimate's limitations and report a verified correction—without mistaking the site for flight approval or a hardware safety certificate.
